02 — Why it's built this way

Engineering choices worth asking about

Five decisions in this codebase that came up in past interviews — happy to walk through any of them in more depth.

01
Idempotent by event ID

Every event carries a unique ID. Replaying one returns the original result instead of mutating stock a second time — safe under retries or duplicate deliveries.

02
Explainable, not opaque

Risk scores come from named, readable rules — coverage days, reorder point, lead-time demand — not a black-box model. The factors are returned alongside the score.

03
Immutable audit trail

Every inventory change and every alert becomes its own audit record, so any state can be traced back to the exact event that caused it.

04
Graceful evolution

SQLite runs locally with zero setup. Docker Compose swaps in PostgreSQL with no application code changes — same models, same queries.

05
Security-ready boundary

API keys load from environment variables, and the dependency-injection layer leaves a clean seam for adding RBAC without restructuring routes.

06
Deterministic decisions

No LLM sits between an event and a stock mutation. The parts that decide are plain rules; anything probabilistic stays out of the critical path.
